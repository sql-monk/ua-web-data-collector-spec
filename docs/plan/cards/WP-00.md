## Scope

Створити відтворюваний каркас репозиторію, у якому всі наступні WP працюють незалежно: Python-проєкт із lockfile, CLI-контракт §16.2, тестова інфраструктура з забороною мережі, lint/type/secret-scan, CI, Docker images та Compose profiles, web scaffold.

## Out of scope

Будь-яка доменна логіка: контракти (WP-01C), міграції (WP-01A), Mongo validators (WP-01B), fetch/discovery/translation, адаптери, реальні API endpoints (WP-11A), екрани GUI (WP-11C), observability stack наповнення (WP-12). Стаби, які WP-00 створює для health/migrate/ensure-mongo, явно позначаються як стаби і замінюються власниками.

## Спільні правила для всіх під-PR

- Owned files — лише перелічені в під-PR. Forbidden: `docs/research/**`, `TECHNICAL_SPECIFICATION.md` (крім одноразової правки назв CLI у §16.2, якщо фінальні назви відрізняються — це єдина дозволена зміна ТЗ, §16.2), `REVIEW.md`.
- Версії залежностей pinned через `uv.lock`/`package-lock.json`; Docker images — tag + digest.
- Українська мова у README/коментарях користувацького рівня; ідентифікатори — англійською.
- Наступні WP додають свої залежності у `pyproject.toml` самостійно (алфавітний порядок у списку, щоб мінімізувати конфлікти) і перегенеровують `uv.lock`; WP-00 фіксує лише foundation-залежності.

## PR1 — `wp/00-1-python-ci`: Python foundation + CI

### Owned files

`.python-version`, `pyproject.toml`, `uv.lock`, `src/collector/**`, `tests/**`, `.pre-commit-config.yaml`, `.github/workflows/ci.yml`, `.github/ISSUE_TEMPLATE/work-package.md`, `.github/pull_request_template.md`, `.editorconfig`, `.gitignore` (доповнення), `docs/plan/reports/WP-00/**`.

### Вимоги

1. Python 3.13 (`.python-version`), `uv` + `pyproject.toml` + `uv.lock`; пакет `collector` з layout Додатка A: `src/collector/{contracts,core,fetch,discovery,adapters/{news,vehicles,catalogs},normalization,translation,persistence/{postgres,mongo},workers,orchestration/{compose,swarm},api,telemetry}` — кожен з `__init__.py` і одним реченням docstring про owner-WP.
2. Foundation-залежності: `pydantic>=2`, CLI framework (`typer` або `click` — вибрати й зафіксувати в ADR-0001), `structlog` або stdlib logging із JSON formatter; dev: `ruff`, `mypy`, `pytest`, `pytest-asyncio`, `pytest-socket`, `respx`, `pre-commit`. Не додавати scrapy/httpx/sqlalchemy/pymongo тощо — їх додають власники WP.
3. CLI `collector` (entry point `collector = "collector.cli:app"`) із командами контракту §16.2 як типізованими стабами, що повертають exit code 2 і повідомлення `not implemented: owned by WP-XX`:
   - `collector db ensure-mongo --validators --indexes` (WP-01B), `collector db migrate` (WP-01A);
   - `collector e2e --source <name> --offline` (WP-14);
   - `collector release build --watermark <w> --output <dir>`, `collector release verify --manifest <path>` (WP-11A);
   - `collector worker <role>` для ролей §7.6 (`discovery|fetch|browser|parse|projector|translation|export|maintenance`) (WP-01D);
   - `collector api`, `collector scheduler`, `collector controller` (WP-11A/01D);
   - `collector version` — реальна: друкує package version, Git SHA (з env `COLLECTOR_GIT_SHA` або `unknown`) і schema version placeholder.
4. `tests/` за Додатком A: `unit/`, `contract/`, `integration/`, `e2e/`, `fixtures/` з `.gitkeep`; `tests/conftest.py` з маркерами `live`, `integration`, `e2e`; **мережа заблокована за замовчуванням** через `pytest-socket` (`--disable-socket` у `pyproject` addopts, `--allow-hosts=127.0.0.1,::1` для integration), тест, який доводить блокування.
5. `ruff` (lint + format, line length 100, правила: E, F, I, B, UP, S для `src`), `mypy --strict` для `src`, pytest config (`asyncio_mode=auto`, markers).
6. `.pre-commit-config.yaml`: ruff, ruff-format, gitleaks (secret scan), end-of-file/trailing-whitespace, markdownlint-cli2 для `*.md`.
7. `.github/workflows/ci.yml`: на push/PR — `uv sync --frozen`, `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src`, `uv run pytest -m "not live"`, gitleaks; concurrency group per branch; secrets лише з GitHub Environments (нічого не hardcode). Крок `docker compose config --quiet` додається у PR2.
8. `.github/ISSUE_TEMPLATE/work-package.md` за §17.3 і `pull_request_template.md` за §17.1 (зміни, тести з виводом, fixture provenance, ризики, як вимкнути/відкотити, що не перевірено live, посилання на звіти етапів).
9. Unit-тести: CLI `--help` містить усі команди вище; кожен стаб повертає код 2 і назву owner-WP; `version` працює; network block працює.

### Команди перевірки

```bash

uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest -m "not live"
uv run collector --help
```

### Acceptance

- `uv run collector --help` показує всі команди §16.2; назви збігаються з §16.2 або §16.2 оновлено в цьому PR з поясненням;
- тест доводить, що socket-з'єднання у звичайному тесті кидає виняток;
- `gitleaks` чистий; жодного `.env` у git;
- `ci.yml` валідний (`actionlint`, якщо доступний; інакше `python -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))"`).

### Rollback/disable

PR не має runtime-ефекту; відкат — revert merge commit.

## PR2 — `wp/00-2-docker-compose`: images + Compose profiles

### Owned files

`Dockerfile`, `deploy/compose/**`, `docker-compose.yml`, `.dockerignore`, `src/collector/api/health.py` (стаб health — далі owner WP-11A), `src/collector/cli.py` (лише команди `api`/`db migrate`/`db ensure-mongo` стаби → мінімальна реальна поведінка для health), `.github/workflows/ci.yml` (додати compose/build кроки), `docs/decisions/0002-docker-compose-single-host.md`.

### Вимоги (§7.5, §13)

1. Один multi-stage image `collector` (uv builder → runtime `python:3.13-slim@sha256:…`), non-root user, read-only rootfs + tmpfs `/tmp`, OCI labels (Git SHA, schema version), `HEALTHCHECK`. Browser image — не тут (WP-02 PR3).
2. `docker-compose.yml` з profiles `core`, `workers`, `browser`, `gui`, `observability`, `tools`; сервіси за таблицею §7.5; workers без `container_name`, без host ports, без local persistent state; `deploy.resources.limits` для всіх; `stop_grace_period` ≥ 90 с для workers.
3. Мережі `ingress`, `backend`, `source-egress`, `provider-egress`, `telemetry` за §7.5; discovery/fetch/browser у `source-egress`, translation у `provider-egress`, api — `backend` + `ingress`, gui бачить лише api.
4. Stateful: `postgres` (PostgreSQL 18, pinned digest), `mongo` (MongoDB 8.0 replica set single-member, pinned digest, keyfile/секрети), `minio` (pinned digest) — named volumes; ports не публікуються назовні (за замовчуванням лише `127.0.0.1` binding через override-файл `deploy/compose/dev.override.yml` для локальної розробки).
5. One-shot `migrate-postgres` (`collector db migrate` — стаб, що перевіряє з'єднання і завершується 0 із повідомленням «no migrations yet; owner WP-01A»), `ensure-mongo` (ініціалізує single-member replica set, якщо не ініціалізовано; validators/indexes — стаб для WP-01B). `api` — мінімальний FastAPI-стаб лише з `GET /api/v1/health/components`, readiness `false`, доки не завершені one-shots (через `depends_on: condition: service_completed_successfully`).
6. Secrets через Docker secrets/files у `deploy/compose/secrets/*.example`; реальні файли в `.gitignore`; жодного секрету в image layer або `ARG`.
7. Healthcheck кожного сервісу перевіряє process + критичну dependency; `scheduler` — singleton (стаб-процес, що бере advisory lease — реалізація WP-01D; тут лише placeholder-команда `collector scheduler`, що тримає процес живим і логує, що lease-логіка ще не реалізована).
8. Документована команда clean-host start: `docker compose --profile core --profile workers --profile gui up -d --wait` — у PR2 profile `gui` може бути відсутнім до PR3; тоді acceptance виконується для `core` + `workers`, а `gui` додається у PR3.
9. CI: `docker compose config --quiet`, `docker build` image `collector`, SBOM (`syft` або `docker sbom`, якщо доступно; інакше — зафіксувати як `operationally unverified` у звіті), vulnerability scan (`trivy`, якщо доступний).

### Команди перевірки

```bash
docker compose config --quiet
docker compose build --pull
docker compose --profile core --profile workers up -d --wait
docker compose ps
docker compose down -v
uv run pytest -m "not live"
```

### Acceptance (§16.3, R-51, R-55)

- чистий host піднімає `core` + `workers` однією командою; всі сервіси `healthy`; workers — стаби, які живі й не падають;
- restart (`docker compose restart`) не втрачає дані named volumes (перевірити маркерним записом у postgres/minio);
- `docker compose config` не містить `container_name` для workers, не містить Docker socket mount у жодному сервісі, не містить public port крім `gui`/dev-override;
- images non-root (перевірити `docker inspect` → `Config.User`), read-only rootfs у compose;
- жоден secret не потрапив у image (`docker history`, `docker run --rm collector env`).

## PR3 — `wp/00-3-web-scaffold`: React/TypeScript/Vite scaffold + GUI image

### Owned files

`web/**`, `deploy/compose/gui/**` (Nginx конфіг), `docker-compose.yml` (додати `gui` до profile `gui`), `.github/workflows/ci.yml` (web кроки).

### Вимоги (§7.7, §8, §13)

1. `web/` з Vite + React + TypeScript strict, ESLint + Prettier, Vitest + Testing Library, Playwright Test; `package-lock.json`; Node 24 LTS у `.nvmrc`.
2. Структура `src/{api,components,features,routes}/`, `tests/{unit,e2e}/`; одна placeholder-сторінка українською «UA Web Data Collector — operator GUI» з route-level code splitting (React Router) і заготовкою під generated OpenAPI client (`src/api/README.md` описує, що клієнт генерується з OpenAPI у WP-11C).
3. Заборонено `localStorage/sessionStorage` для токенів — ESLint rule `no-restricted-globals`/`no-restricted-properties` для цих API з коментарем-причиною.
4. Multi-stage image: `node` builder → `nginxinc/nginx-unprivileged` (pinned digest), non-root, security headers і restrictive CSP у `deploy/compose/gui/nginx.conf`, same-origin reverse proxy `/api` → `api:8000`.
   - Мережі (з gate 3 PR2, CR-14/SEC L-2, §7.5 «API — лише OIDC egress»): gui↔api через окрему **internal** мережу (напр. `frontend`), у `ingress` лишається лише `gui`; `api` прибрати з `ingress`. Не проксіювати `/api/v1/health/components` назовні без auth (або лише `ready`/`ok`) до OIDC у WP-11A.
5. Скрипти `npm run lint`, `npm run test`, `npm run build`, `npm run test:e2e` (E2E — один smoke-тест, що сторінка рендериться проти `vite preview`; проти Docker stack — у WP-11C).

### Команди перевірки

```bash
cd web && npm ci && npm run lint && npm run test && npm run build && npm run test:e2e
docker compose config --quiet
docker compose --profile core --profile gui up -d --wait
```

### Acceptance

- всі команди зелені; `gui` container `healthy`, `curl http://localhost/` віддає сторінку, `curl http://localhost/api/v1/health/components` проксіюється до api;
- CSP/security headers присутні у відповіді; container non-root;
- clean-host команда §16.2 `docker compose --profile core --profile workers --profile gui up -d --wait` зелена — це закриває acceptance усього WP-00.
